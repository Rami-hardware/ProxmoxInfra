# AGENTS.md

Guidance for AI coding agents working in this repo.

## Repo Overview

Homelab infra: Proxmox VMs provisioned with Terraform, configured with Ansible, apps deployed via GitOps (ArgoCD + Image Updater) on K3s. Branches: `main` / `staging` / `development` — CI runs on push to any of them.

## Load-Bearing Quirks — DO NOT "FIX"

- `Ansbile/` is misspelled on purpose — referenced by workflows, ArgoCD Application CRs, and `.ansible-lint`. Never rename.
- `Terraform/terrraform.tf` (3 r's) is the real terraform block file. Never rename.
- `.argocd-source-*.yaml` files under `Ansbile/argocd-apps/*/` are auto-generated by ArgoCD Image Updater git write-back. Never hand-edit.
- `Ansbile/group_vars/vault.yml` is referenced by `git-k3s-server.yml` but does not exist in the repo (local-only).

## Terraform (`Terraform/`)

- Provider `bpg/proxmox` pinned `~> 0.70.1`. No `required_version`. No remote backend — **state is committed to git**.
- VMs defined as a `map(object)` in `terraform.tfvars`. Map keys are state addresses: **renaming a key destroys the VM**.
- `lifecycle.ignore_changes` covers `disk`, `initialization`, `clone`, `hostpci`, `cpu` and more — don't remove.
- Manual apply requires `parallelism=1` (Proxmox API race conditions) and `-target` per VM. CI deliberately does NOT apply VMs — plan only, with a destroy/replace guard that fails the pipeline.
- Provider values come from `TF_VAR_*` env vars (GitHub secrets) — never hardcode tokens.

### Commands (run from `Terraform/`)

```bash
terraform init -backend=false
terraform fmt -check -recursive
terraform validate
terraform plan -input=false -no-color -detailed-exitcode -out=tfplan
```

## Ansible (`Ansbile/`)

- Inventory: `inventory.ini` (groups = `gateway-vm`, `media-vm`, `monitoring-vm`, `git-k3s-server-vm`, `host-node`). Group names must match `group_vars/<group>.yml` filenames.
- Playbooks: one per host (`gateway-server.yml`, `media-server.yml`, `monitoring-server.yml`, `git-k3s-server.yml`).
- 17 roles under `Ansbile/roles/`. Deploy order in CI: gateway → monitoring → media → git-k3s.
- Secrets: `group_vars/all.yml` is fully vault-encrypted; also `roles/scraparr/vars/vault.yml`. Vault password via `--vault-password-file ~/.vault_pass` (CI writes it from `ANSIBLE_VAULT_PASSWORD` secret). Never commit plaintext secrets.

### Conventions (enforced — match existing code)

- **FQCN always**: `ansible.builtin.template`, `community.docker.*` — no short module names.
- **Role vars prefixed** `<role_name>_` (e.g. `k3s_server_version`, `grafana_data_dir`).
- **All config rendered from Jinja2 templates** (`*.yml.j2`) — no inline hardcoded content in tasks.
- **IPs referenced via `hostvars[host]['ansible_host']`** from inventory — single source of truth, never hardcode IPs.
- Command/shell tasks need explicit `changed_when` / `failed_when`.

### Commands

```bash
ansible-galaxy collection install -r Ansbile/requirements.yml
ansible-playbook -i Ansbile/inventory.ini Ansbile/gateway-server.yml --syntax-check --vault-password-file ~/.vault_pass
ansible-lint Ansbile/
ansible-playbook -i Ansbile/inventory.ini Ansbile/gateway-server.yml --check --diff --vault-password-file ~/.vault_pass
```

(`--check` dry run only works on the gateway playbook — media/gateway have Docker tasks that break in check mode.)

## ArgoCD Apps (`Ansbile/argocd-apps/`)

App changes here do NOT need CI — ArgoCD polls and syncs automatically (self-heal + prune).

Per-namespace dir (`media/`, `monitoring/`, `network/`):

- `kustomization.yaml` — `resources:` list + `images:` block with `newTag` (the Image Updater write-back target).
- One plain multi-doc YAML per app (Namespace + PV + PVC + Deployment + Service/NodePort pattern — see `jellyfin.yaml`).
- To add an app: create its YAML, list it in that dir's `kustomization.yaml`. Apps needing secrets stay in Ansible `k3s_apps_list` (currently only `adguard-exporter`).

Excluded from ansible-lint via root `.ansible-lint` (`exclude_paths: [Ansbile/argocd-apps/]`).

## CI/CD (`.github/workflows/`)

Self-hosted runner (small disk — prune docker/caches when adding build steps). Entry `main.yml` → reusable workflows: `testing.yml`, `deploy.yml`, `build-image.yml`, `security.yml`, `notify.yml`. Composite actions: `setup-ssh-vault`, `setup-terraform-mirror`, `cleanup-secrets`.

- Runner has no registry access — Terraform providers install via filesystem mirror (`setup-terraform-mirror`), currently seeded for `bpg/proxmox 0.70.1`. Bumping the provider requires updating the mirror action too.
- `setup-terraform` uses `terraform_wrapper: false` — required for `-detailed-exitcode` to work.
- `terraform apply` in `deploy.yml` is commented out on purpose (manual applies only).
- Discord notifications via webhook secrets.
